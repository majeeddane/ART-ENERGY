# ART ENERGY — ارت إنيرجي

موقع تعريفي ثنائي اللغة (العربية افتراضيًا مع RTL، والإنجليزية مع LTR) لشركة **ارت إنيرجي** — دعاية وإعلان، تسويق رقمي، صناعة محتوى، إنتاج إعلامي، وبناء علامات تجارية.

بُني الموقع بـ **Next.js 15 + TypeScript + Tailwind CSS**، مع تجربة بصرية مستوحاة من استوديو صوت حي: موجات صوتية، Equalizer، أسطوانة فينيل دوّارة، وخط زمني على شكل نغمات موسيقية.

> جميع النصوص والأسعار والخدمات مأخوذة من البروفايل المرفق فقط. لا توجد إحصاءات أو عملاء أو شهادات أو أسماء فريق مُختلقة.

## 1. التشغيل المحلي

### المتطلبات

- Node.js **20.9 أو أحدث** (يُنصح بـ 20 LTS أو 22 LTS)
- npm 10+

### الخطوات

```bash
cd art-energy
npm install
cp .env.example .env.local
npm run dev
```

ثم افتح:

- العربية: <http://localhost:3000>
- English: <http://localhost:3000/en>
- لوحة التحكم: <http://localhost:3000/admin> (تتطلب `ADMIN_PASSWORD` في `.env.local` — راجع القسم 3)

### أوامر مفيدة

| الأمر | الوظيفة |
| --- | --- |
| `npm run dev` | تشغيل بيئة التطوير |
| `npm run build` | بناء نسخة الإنتاج |
| `npm start` | تشغيل نسخة الإنتاج بعد البناء |
| `npm run typecheck` | فحص TypeScript |
| `npm run lint` | فحص ESLint |

## 3. لوحة التحكم — إدارة كل المحتوى

اللوحة هي الطريقة الأساسية لتعديل الموقع. كل ما تراه في الصفحات — النصوص، القوائم، الأسعار، خدمات الإنتاج، الباقات، بيانات التواصل، الروابط الاجتماعية، الشعار والصور، وحتى الأقسام المخفية — يمكن تعديله من `/admin` دون لمس الكود.

### الدخول

1. شغّل الموقع ثم افتح <http://localhost:3000/admin>.
2. سيتم تحويلك إلى `/admin/login`.
3. أدخل كلمة المرور الموجودة في `ADMIN_PASSWORD` داخل `.env.local`.

عند أول تشغيل، أنشئ الملف من القالب:

```bash
cp .env.example .env.local
```

ثم بدّل القيمتين:

```env
ADMIN_PASSWORD=كلمة-مرور-طويلة-وفريدة
ADMIN_SESSION_SECRET=سلسلة-عشوائية-طويلة-32-حرفًا-على-الأقل
```

- الجلسة محفوظة في كوكي `ae_admin` موقّع بـ HMAC-SHA256 ومدة صلاحيته 7 أيام (HttpOnly + SameSite=Lax + Secure في الإنتاج).
- الدخول محدود بـ 8 محاولات كل 10 دقائق لكل IP.
- زر «تسجيل الخروج» في الشريط الجانبي يمسح الجلسة فورًا.
- صفحة اللوحة `noindex, nofollow` ولا تظهر في محركات البحث.

> لا تضع كلمة المرور في README أو في أي ملف يُرفع إلى Git. غيّر كلمة المرور في `.env.local` محليًا وفي متغيرات بيئة الاستضافة عند النشر.

### ماذا يمكن تعديله؟

| الصفحة | ما تتحكم به |
| --- | --- |
| **نظرة عامة** | حالة التخزين، رفع الصور، آخر حفظ، عدد العناصر، والأقسام المفعّلة |
| **محتوى الموقع** | كل نصوص العربية والإنجليزية، أقسام الصفحة، القوائم، الأسعار، نصوص النموذج، وSEO |
| **الأقسام المخفية** | إضافة/تعديل/حذف/ترتيب الأعمال والعملاء والفريق والمقالات، مع الصور والروابط والتواريخ، وتفعيل ظهور كل قسم |
| **الإعدادات والهوية** | الهاتف والبريد وواتساب، الروابط الاجتماعية، نطاق الحملة، الشعار وصورة الهيرو وOG والأيقونة، الكلمات المفتاحية، ومفاتيح الأقسام |
| **الصور والملفات** | رفع عدة صور، معاينتها، نسخ روابطها، وحذفها مع التحقق من عدم استخدامها |

### تفاصيل مهمة

- **اللغتان معًا:** لكل قسم تبويبان «العربية / English». زر «نسخ نصوص الإنجليزية» ينسخ البنية والنصوص من اللغة الأخرى لتسريع الترجمة.
- **الترتيب:** كل قائمة (خدمات، باقات، مراحل، مزايا…) فيها أزرار ↑ ↓، ويمكن حذف أي عنصر أو إضافة عنصر جديد.
- **الأسعار:** تُعدَّل من «محتوى الموقع» داخل `packages.plans` و`production.items`. سياسة «ابتداءً من» لخدمات الإنتاج تبقى كما هي.
- **الأقسام المخفية:** لا تظهر إلا عند تفعيل مفتاحها من «الإعدادات» أو من صفحة القسم نفسه. إذا فُعّل القسم بدون عناصر، يظهر مكان بديل أنيق.
- **الصور:** الحد الأقصى 4 ميجابايت، والصيغ: JPG / PNG / WebP / AVIF / GIF. يمكن اختيار صورة من المكتبة أو رفع صورة جديدة أو استخدام رابط مباشر.
- **الحفظ:** لا يظهر التعديل على الموقع إلا بعد الضغط على «حفظ التغييرات». تظهر حالة «تغييرات غير محفوظة» في الشريط السفلي، ويظهر تحذير عند مغادرة الصفحة.
- **المعاينة:** أزرار «عرض الموقع» في الأعلى تفتح النسختين العربية والإنجليزية في تبويب جديد.

### أين تُحفظ البيانات؟

- **في التطوير:** ملف `content/runtime.json` داخل المشروع. يُنشأ تلقائيًا عند أول حفظ، وهو مستثنى من Git.
- **في الإنتاج:** جدول `site_content` في Postgres (JSONB). يُنشأ الجدول تلقائيًا عند أول قراءة/حفظ.
- **الصور:** Vercel Blob أو Cloudinary، أو `public/uploads` في التطوير فقط.

> نسخة احتياطية سريعة من Postgres:
>
> ```sql
> select data from site_content where id = 'site';
> ```
>
> احفظ الناتج بصيغة JSON. يمكن إعادته لاحقًا عبر `update` أو من خلال اللوحة.

## 4. تعديل المحتوى الافتراضي (للمطوّر)

> المحتوى التشغيلي يُحفظ في قاعدة البيانات (أو `content/runtime.json`) عبر اللوحة. الملف `content/site.ts` هو **المصدر الافتراضي** الذي يُستخدم عند أول تشغيل وعند إضافة حقول جديدة، وليس مكان التعديل اليومي.

كل المحتوى الافتراضي في:

```text
content/site.ts
```

داخله قاموسان: `ar` و `en`، ويجب تعديل القيم في الاثنين للحفاظ على تطابق اللغتين. عند إضافة حقل جديد إلى القاموس، يظهر تلقائيًا في اللوحة ويُملأ في البيانات المحفوظة القديمة عبر الدمج الذكي (`src/lib/site-data.ts`).

### الأسعار

- **الباقات الشهرية**: `packages.plans[].price`
- **خدمات الإنتاج المستقلة**: `production.items[].price` (تُعرض بـ «ابتداءً من»)
- **الحملة الكبرى**: نطاق `10,000 – 15,000` موثّق في `packages.builder.campaignHint`

حاسبة الباقة (`PackageBuilder`) تجمع **فقط** الأسعار المذكورة أعلاه، وتفصل بين الإجمالي الشهري والإجمالي مرة واحدة. لا تُضاف أي أسعار غير موجودة في البروفايل.

### جهة الاتصال

في أعلى `site.ts`:

```ts
export const siteConfig = {
  email: "Waterkind0@gmail.com",
  phoneDisplay: "+966 55 789 7425",
  phoneHref: "tel:+966557897425",
  whatsapp: "966557897425",
  // ...
};
```

### الروابط والأقسام

- أسماء الأقسام: `nav`
- الأقسام المخفية: `hidden`
- نصوص النموذج: `contact.form`

## 5. تغيير الشعار والألوان والخطوط

### الشعار

- أسهل طريقة: **الإعدادات والهوية → الشعار والصور**، وارفع الشعار (PNG بخلفية شفافة أو SVG). اترك الحقل فارغًا لاستخدام الشعار المرسوم.
- من نفس الصفحة تتحكم أيضًا في صورة الهيرو، صورة المشاركة (OG)، والأيقونة (Favicon).
- شعار الواجهة الافتراضي مكوّن SVG في:

  ```text
  src/components/brand/Logo.tsx
  ```

  عدّل المسارات داخله أو استبدل المكوّن بشعار العميل الرسمي (يُفضّل SVG).

- أيقونة المتصفح الافتراضية: `public/icon.svg`
- صورة المشاركة الافتراضية: `public/og.png` (1200×630)
- يمكن أيضًا استبدال العمل الفني للهيرو في `public/images/media-art.webp` مع الحفاظ على النسبة.

### الألوان

متغيرات التصميم في `src/app/globals.css`:

```css
:root {
  --canvas: #fbf8f1;
  --teal: #139caa;
  --gold: #d1a246;
  --orange: #f28c28;
  --deep: #07262f;
  /* ... */
}
```

وتوجد نسخة للوضع الداكن تحت `[data-theme="dark"]`. كما تحتوي `tailwind.config.ts` على تدرجات `teal` و`gold` و`orange`.

### الخطوط

الخطوط **مستضافة محليًا** داخل `public/fonts/` ولا يعتمد الموقع على Google Fonts وقت البناء أو التشغيل:

```text
public/fonts/
├─ ibm-plex-sans-arabic-400.woff2
├─ ibm-plex-sans-arabic-600.woff2
├─ ibm-plex-sans-arabic-700.woff2
└─ space-grotesk-latin-variable.woff2
```

تُعرَّف عبر `@font-face` في `src/app/globals.css`، وتُربط بالمتغيرين `--font-arabic` و`--font-grotesk`. نستخدم `font-display: optional` لتجنّب تأخير الرسم الأول وتبديل الخطوط المرئي (CLS).

لاستبدال الخط: ضع ملفات `woff2` الجديدة في `public/fonts/` وحدّث قواعد `@font-face` والمتغيرات. تجنّب `next/font/google` إن كانت بيئة البناء بلا اتصال بـ Google؛ فهو يفشل أثناء `npm run build` عند حجب الشبكة.

## 6. إظهار الأقسام المخفية

أقسام «الأعمال، العملاء، الفريق، المدونة» مخفية افتراضيًا. تُدار بالكامل من اللوحة:

1. افتح **الأقسام المخفية** أو **الإعدادات والهوية**.
2. أضف العناصر المطلوبة (صور، عناوين، تصنيفات، روابط، تواريخ).
3. فعّل مفتاح «إظهار القسم».
4. اضغط **حفظ التغييرات**.

المفاتيح الأربعة موجودة أيضًا في `.env.local` كقيم افتراضية أولية فقط:

```env
NEXT_PUBLIC_SHOW_WORK=true
NEXT_PUBLIC_SHOW_CLIENTS=true
NEXT_PUBLIC_SHOW_TEAM=true
NEXT_PUBLIC_SHOW_JOURNAL=true
```

> بعد أول حفظ من اللوحة تصبح قيمة المفتاح المحفوظة في قاعدة البيانات هي المرجع. لا تضف عملاء أو أرقامًا أو شهادات غير موثّقة.

## 7. ربط نموذج التواصل

الواجهة الخلفية في:

```text
src/app/api/contact/route.ts
```

المزوّدات تُجرّب بالترتيب، ويكفي ضبط واحد:

### الخيار 1 — Formspree (الأسهل)

1. أنشئ حسابًا على <https://formspree.io>
2. أنشئ Form جديدًا وانسخ رابط الـ endpoint.
3. أضف إلى `.env.local`:

   ```env
   FORMSPREE_ENDPOINT=https://formspree.io/f/xxxxxxxx
   ```

### الخيار 2 — Resend (بريد من السيرفر)

1. أنشئ مفتاح API من <https://resend.com>
2. وثّق نطاقك.
3. أضف:

   ```env
   RESEND_API_KEY=re_xxxxxxxx
   CONTACT_FROM_EMAIL="ART ENERGY <website@your-domain.com>"
   CONTACT_TO_EMAIL=Waterkind0@gmail.com
   ```

### الخيار 3 — Webhook عام

```env
CONTACT_WEBHOOK_URL=https://hooks.zapier.com/...
```

### السلوك عند عدم الربط

إذا لم يُضبط أي مزوّد، يعيد الـ API الحالة `503` مع `fallback: true`، وتعرض الواجهة رسالة واضحة وزرّين: إرسال الطلب عبر **واتساب** أو **البريد الإلكتروني** مع تجهيز نص الرسالة تلقائيًا.

### الحماية

- التحقق من الحقول من السيرفر والعميل.
- Honeypot ضد البوتات.
- حدّ معدّل بسيط: 6 طلبات / 10 دقائق لكل IP.
- تنظيف النصوص وتحديد أطوالها.

> لمواقع الإنتاج الكبيرة، استبدل حدّ المعدّل في الذاكرة بخدمة مثل Upstash Redis.

## 8. البناء والنشر

### Vercel

1. ارفع المشروع إلى GitHub.
2. في Vercel: **Add New → Project** واختر المستودع.
3. **Root Directory**: `art-energy` (إذا كان المستودع يحتوي مجلدات أخرى).
4. Framework: **Next.js** (يُكتشف تلقائيًا).
5. أضف متغيرات البيئة من `.env.example`، وأهمها:

   ```env
   NEXT_PUBLIC_SITE_URL=https://your-domain.com
   ADMIN_PASSWORD=...
   ADMIN_SESSION_SECRET=...
   DATABASE_URL=postgresql://...
   BLOB_READ_WRITE_TOKEN=...
   ```

6. **قاعدة البيانات (إلزامية على Vercel):** أنشئ قاعدة Postgres مجانية من <https://neon.tech>، وانسخ Connection String إلى `DATABASE_URL`. يُنشئ الموقع جدول `site_content` تلقائيًا.
7. **الصور (إلزامية للحفظ الدائم):** أنشئ Blob Store من تبويب **Storage** في Vercel وانسخ `BLOB_READ_WRITE_TOKEN`. البديل: إعدادات Cloudinary.
8. Deploy.

> بدون `DATABASE_URL` سيعمل الموقع للعرض فقط، لكن أي حفظ من اللوحة على Vercel سيفشل برسالة واضحة. بدون Blob/Cloudinary تُرفض الصور المرفوعة في الإنتاج.

### Netlify

1. **Add new site → Import an existing project**.
2. Base directory: `art-energy`.
3. Build command: `npm run build`.
4. Publish directory: `.next`.
5. ثبّت إضافة **Next.js Runtime** (Netlify تكتشفها تلقائيًا في الغالب).
6. أضف `DATABASE_URL` (Neon/Postgres) و`ADMIN_PASSWORD` و`ADMIN_SESSION_SECRET` و`BLOB_READ_WRITE_TOKEN` أو إعدادات Cloudinary.
7. أضف متغيرات البيئة ثم انشر.

### بعد النشر

- اضبط `NEXT_PUBLIC_SITE_URL` على الدومين النهائي **قبل** البناء (يؤثر على canonical وhreflang وsitemap وJSON-LD).
- غيّر `ADMIN_PASSWORD` و`ADMIN_SESSION_SECRET` إلى قيم قوية خاصة بالإنتاج.
- تحقق من:
  - `https://your-domain.com/admin` (يجب أن يطلب كلمة المرور)
  - `https://your-domain.com/robots.txt`
  - `https://your-domain.com/sitemap.xml`
  - `https://your-domain.com/og.png`
- أرسل خريطة الموقع إلى Google Search Console.

## 9. الأداء والوصولية

- صور بصيغة WebP مع `next/image` وأحجام AVIF/WebP.
- تحميل كسول للمشاهد الثقيلة (Three.js) مع بديل ثابت.
- دعم `prefers-reduced-motion` وإيقاف الحركات التلقائية.
- تباين ألوان وفق WCAG AA.
- تنقّل كامل بلوحة المفاتيح، رابط تخطي المحتوى، وتركيز واضح.
- الصوت اختياري ومكتوم افتراضيًا.
- تبديل اللغة والوضع الداكن محفوظان في المتصفح.

### اختبار Lighthouse

```bash
npm run build
npm start
```

ثم افتح Chrome → Lighthouse على `http://localhost:3000` (وضع سطح المكتب والجوال).

**نتائج النسخة الحالية** (بناء إنتاجي، اتصال هادئ، دون تبويبات أخرى مفتوحة):

| الوضع | Performance | Accessibility | Best Practices | SEO |
| --- | --- | --- | --- | --- |
| الجوال | **93 – 94** | 100 | 100 | 100 |
| سطح المكتب | **99** | 100 | 100 | 100 |

على الجوال: FCP ≈ ‏2.0s، LCP ‏2.8–2.9s، TBT ‏50–60ms، CLS ‏0، SI ‏2.1–2.4s. على سطح المكتب: FCP ‏0.5s، LCP ‏0.8s، TBT ‏0ms، CLS ‏0، SI ‏0.9s.

قد تنخفض الدرجة إلى 82–88 إذا كان الجهاز مشغولًا بتبويبات/عمليات أخرى أثناء القياس، لذا قِس على جهاز هادئ.

**ملاحظة تصميمية:** شاشة التحميل (Preloader) تعمل على سطح المكتب فقط. على الجوال تُخفى عبر CSS لأنها تغطي الهيرو وتؤخر LCP على الشبكات البطيئة؛ هذا قرار أداء مقصود وليس خطأً.

## 10. ملاحظات مهمة

- لا توجد أسعار مُختلقة: كل الأرقام من البروفايل.
- كل المحتوى القابل للتغيير يُدار من `/admin` ويُحفظ في Postgres أو `content/runtime.json`؛ لا حاجة لإعادة بناء الموقع بعد كل تعديل.
- الصفحات العامة تُرسل ثابتة مع `revalidate` ساعة، ويُعاد التحقق منها فورًا (`revalidatePath`) بعد كل حفظ من اللوحة — تعديلات العميل تظهر مباشرة دون إعادة بناء.
- الباقة الوسطى مميزة بصريًا فقط، دون ادعاء «الأكثر طلبًا» غير الموثّق.
- قسم الحملات يعرض النطاق `10,000 – 15,000` كما ورد (قابل للتعديل من الإعدادات).
- خريطة الموقع وhreflang يشيران إلى `/` و`/en`.
- لتغيير الخط الافتراضي أو الاتجاه، راجع `(ar)/layout.tsx` و`(en)/layout.tsx` و`RootDocument.tsx`.

## 11. ما يلزم استلامه من العميل لاستكمال الموقع

- شعار رسمي بصيغة SVG أو AI/EPS (الحالي مُعاد بناؤه من البروفايل، ويمكن رفعه من اللوحة).
- صور/فيديوهات حقيقية للمشاريع إن رغب العميل بإظهار قسم الأعمال.
- أسماء العملاء وشعاراتهم — بموافقة خطية.
- أسماء وأدوار فريق العمل وصورهم.
- روابط التواصل الاجتماعي الرسمية (لم تُضف لعدم ورودها في البروفايل، وتُضاف من الإعدادات).
- العنوان الفعلي إن أراد إضافته (غير موجود حاليًا).
- بريد استقبال الطلبات النهائي أو رابط Formspree/Resend.
- الدومين النهائي لضبط `NEXT_PUBLIC_SITE_URL`، وقاعدة Postgres ومساحة صور سحابية للإنتاج.
